# Browser AI Bridge — Roadmap

> Живой документ. Актуально на 2026-08-19. Дополняем вместе: идеи, приоритеты, вопросы.

## 0. Сделано (закрытые этапы)

### P1 — закрыт полностью
- [x] Streaming + tool-loop: `stream:true` исполняет тулы и стримит финальный ответ (runToolLoopStream, OpenAI-совместимый формат).
- [x] Интерактивный permission-промпт: PermissionBroker + Runtime.interactive + эндпоинты pending/approve/deny + UI-карточка в дашборде (1 раз/сессию/навсегда).
- [x] Персистентность на диск: сессии + аудит + конфиг в `~/.browser-ai-bridge/` (атомарная запись, restore после рестарта).
- [x] Live-апдейты дашборда: SSE `GET /v1/events` + хук `useBabEvents` (PermissionPrompt, Logs, Sessions, Providers).
- [x] fs-тулы: `fs.edit` (search/replace + unified patch), `fs.search`, `fs.glob`, `fs.exists`, `fs.delete` + правила прав.

### Качество ответов (6b)
- [x] Resilient selectors + fallback-чтение для 4 провайдеров.
- [x] CDP interception: `CDPClient.captureStream()` + `CdpTokenStream` + SSE-парсеры для Gemini/ChatGPT/Claude/DeepSeek + `detectBlockError` (auth/rate-limit/captcha). `stream()`/`send()` теперь CDP-first с DOM-fallback.
- [x] Retry при обрыве чтения (withRetry/withConnectionRetry).

### Инфраструктура
- [x] Топологический порядок сборки + `clean` чистит dist и tsbuildinfo.
- [x] Честные данные дашборда: `/health` (degraded при 0 провайдеров), `/v1/tools` (реальные тулы + режимы прав), `/v1/metrics` (JSON), убраны фейковые значения.
- [x] Дизайн-система (первый заход): ui.tsx примитивы, анти-флеш тема, шрифт Inter, gray-750.

## 3. Свежие идеи (план реализации, 2026-08-19)
- [x] **Промпты под конкретную IDE**: Cursor / VS Code / Continue / OpenCode (detectIde + секции).
- [x] **Вербатим-кэш ответов**: повторные запросы из кэша (только stateless API, финальные ответы).
- [x] **Токен-эстимация и лимиты на сессию**: прогресс-бар контекста в Sessions.
- [x] **Мульти-аккаунт ротация**: несколько браузерных профилей на провайдер (`--accounts N`), авто-переключение при rate-limit/CAPTCHA.
- [x] **Рейтинг надёжности провайдеров** + авто-выбор «best working» (здоровье/латентность/ошибки).
- [x] **«Командный режим»**: один BAB-сервер, несколько IDE-клиентов с изоляцией сессий и RBAC (admin/member, Bearer-ключи, `bab team`).
- [x] **Прокси-кэш ответов**: persistent `ResponseCache` (`--cache <dir>`, `/v1/cache`, privacy-фильтр секретов).
- [x] **Веб/мобильный клиент (PWA)**: дашборд стал устанавливаемым (manifest + service worker + иконки).
- [x] **Экспорт диагностики одним файлом**: `bab diagnose --output <file>` (публичный debug-портал отложен — небезопасно публиковать диагностику).
- [x] **Лендинг/презентация**: `landing/index.html` (одностраничный, светлая/тёмная тема).

## 6. Визуал — зафиксированная концепция

Две аудитории и два входа:
- **Обычные пользователи / вайбкодеры** → отполированное desktop-приложение: «просто и красиво», максимально удобно, минимум технических деталей.
- **Разработчики** → CLI как минимальный вход; опционально то же приложение.

Принцип: просто + красиво, продукт «для людей», но не в ущерб функциональности для dev-аудитории.

К доработке:
- [ ] Онбординг/первый запуск: wizard «подключи провайдер → выбери модель → готово».
- [ ] Полировка тёмной/светлой тем и анимаций.
- [ ] Лендинг/презентация продукта (когда будет что показывать).
- [ ] Референсы для вдохновения — уточнить у владельца.

## 7. Открытые технические вопросы
- Как стримить tool-loop без потери совместимости с IDE (частично решено: runToolLoopStream).
- Как хранить сессии безопасно (секреты не сохраняем, только метаданные/текст).
- Как поднять «много клиентов → один браузер» без конфликтов за вкладку.
