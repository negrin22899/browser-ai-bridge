# Browser AI Bridge — Roadmap

> Живой документ. Актуально на 2026-08-18. Дополняем вместе: идеи, приоритеты, вопросы.

## 0. Сделано в последнем заходе

- Tool execution loop в `/v1/chat/completions` (tool_calls/actions → PermissionEngine → ToolDispatcher → результат обратно, до финального ответа) + `--allow`.
- Дашборд на реальном API: Providers, Logs, Extensions, Settings, Sessions (delete).
- Endpoint'ы: `/v1/audit`, `DELETE /v1/sessions/:id`, `/v1/config`, `/v1/extensions`.
- `cancel()` у провайдера, подключён к abort стрима.
- Graceful shutdown (SIGINT/SIGTERM, uncaughtException/unhandledRejection).
- Полные метрики в `/metrics`.
- Дедупликация BrowserManager, починка CI/тестов/сборки.

## 1. Ближайший горизонт (P1 — делаем в первую очередь)

- [ ] **Интерактивный permission-промпт** — дашборд показывает «AI хочет fs.write/shell.exec», разрешаешь на 1 раз/сессию/навсегда. Делает write/exec тулы юзабельными без `--allow`.
- [ ] **Streaming + tool-loop** — цикл тулов выполняется в не-стриминге, а финальный ответ стримится чанками (сейчас `stream:true` идёт старым путём).
- [ ] **Живые апдейты дашборда** — WebSocket/SSE вместо поллинга (провайдеры, аудит, прогресс тулов, метрики).
- [ ] **Персистентность** — сессии/аудит/история на диск (сейчас всё в памяти, после рестарта пропадает).
- [ ] **Self-healing браузера** — retry/переподключение при обрыве вкладки (код reliability/retry есть, не задействован).

## 2. Продуктовые фичи (P2)

- [ ] E2E для ChatGPT/Claude/DeepSeek (реальный браузер + логин).
- [ ] История чатов + экспорт (markdown/JSON).
- [ ] Интерактивный AI Debugger в дашборде (timeline/replay из `packages/core` — сейчас только библиотека).
- [ ] Multi-provider сессии (Session Fabric: несколько AI параллельно).
- [ ] Глобальные хоткеи + системные уведомления (desktop).
- [ ] Краш-репорты (opt-in) + логирование в файл.
- [ ] Автообновление уже есть в desktop; добавить канал stable/beta.

## 3. Инфраструктура / распространение (P3)

- [ ] npm-пакет `@bab/cli` (`npm i -g @bab/cli`) + автосборка релизов в CI.
- [ ] Docker-образ для headless-сервера (деплой без браузера на машине? — нужен headful Chrome, продумать).
- [ ] Docker/WSL/SSH runtime-провайдеры (сейчас стабы).
- [ ] CDP / Extension браузер-адаптеры (сейчас Playwright, остальное стабы).
- [ ] Plugin marketplace + sandboxing + hot-reload.
- [ ] OAuth-интеграции (GitHub и т.п.).
- [ ] Connection pooling, lazy loading провайдеров, debounce стриминга.
- [ ] Performance budget и бенчмарки; testing-strategy doc.

## 4. Бэклог / рискованные, но интересные идеи

- [ ] Режим «multiple accounts» — несколько браузерных профилей на провайдер.
- [ ] Веб/мобильный клиент поверх API (PWA).
- [ ] Прокси-кэш ответов для экономии (опционально, с уважением к приватности).
- [ ] Токен-эстимация/лимиты на сессию.
- [ ] «Командный режим»: один локальный BAB-сервер, несколько IDE-клиентов с RBAC.
- [ ] Экспорт диагностики одним файлом (уже есть `bab diagnose`) → публичный debug-портал.
- [ ] Рейтинг надёжности провайдеров и авто-выбор «best working» провайдера.

## 6. Визуал — зафиксированная концепция

Две аудитории и два входа:
- **Обычные пользователи / вайбкодеры** → отполированное desktop-приложение: «просто и красиво», максимально удобно, минимум технических деталей.
- **Разработчики** → CLI как минимальный вход; опционально то же приложение.

Принцип: просто + красиво, продукт «для людей», но не в ущерб функциональности для dev-аудитории.

К доработке:
- [ ] Единая дизайн-система (типографика, отступы, плотность, состояния).
- [ ] Онбординг/первый запуск: wizard «подключи провайдер → выбери модель → готово».
- [ ] Полировка тёмной/светлой тем и анимаций.
- [ ] Лендинг/презентация продукта (когда будет что показывать).
- [ ] Референсы для вдохновения — уточнить у владельца.

## 6b. Качество ответов и код-редактирование (приоритет для «работает как Cursor»)

Текущая слабость №1 — сам «ответ» добывается из DOM (поллинг рендера), а не из нативного API:
- [ ] Resilient selectors + fallback-чтение (aria/clipboard/несколько селекторов) для всех 4 провайдеров.
- [ ] CDP-адаптер для более надёжного чтения/ввода.
- [ ] Нативный streaming для API-адаптеров (Google/Anthropic/OpenAI), а не эмуляция поллингом.
- [ ] Retry при обрыве/таём-ауте чтения.

Код-редактирование из IDE уже возможно (AI отдаёт `fs.write` с полным содержимым), но не хватает инструментов и цикла:
- [ ] `fs.edit` (search/replace или unified patch) — безопаснее и экономнее, чем полная перезапись.
- [ ] `fs.search`/`grep`, `fs.glob`, `fs.exists`, `fs.delete`.
- [ ] `git.add/reset/stash` и цикл build/test: `shell.exec` для запуска команд, результат обратно AI.
- [ ] Agentic system-prompt: read → plan → edit → verify (git.diff/build/test) → final.
- [ ] Валидация + retry при битом/обрезанном JSON `{"actions":[...]}` (частый случай на длинном коде).
- [ ] Streaming финального ответа, чтобы IDE показывал токены по мере генерации.
- [ ] Интерактивное подтверждение для write/exec (см. P1) — чтобы правки не были «слепыми».

## 7. Открытые технические вопросы

- Как стримить tool-loop без потери совместимости с IDE.
- Как хранить сессии безопасно (секреты не сохраняем, только метаданные/текст).
- Как поднять «много клиентов → один браузер» без конфликтов за вкладку.
